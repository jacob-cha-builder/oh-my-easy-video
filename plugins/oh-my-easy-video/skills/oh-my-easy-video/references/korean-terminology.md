# 한국어 용어 — 화면과 음성은 항상 일치한다

## 규칙은 하나

**화면에 쓴 글자와 나레이션이 읽는 소리가 같아야 한다.** 기본값은 양쪽 다 한국어다.

이게 왜 규칙인지는 실패 사례를 보면 바로 보인다.

## 실패 사례 (2026-08, `paperthin-explainer`)

| | 화면 | 음성 |
|---|---|---|
| Frame 4 | `re0` | "리제로라는 스킬은…" |
| Frame 5 | `readchk` | "리드첵이라는 스킬은…" |
| Frame 6 | `debloat` | "디블로트라는 스킬은…" |

보는 사람은 화면의 `re0` 와 귀에 들리는 "리제로"를 **머릿속에서 매칭해야 한다.** 설명
영상에서 이건 순수한 인지 비용이다. 아는 사람은 굳이 필요 없고, 모르는 사람은 둘이 같은
것인지조차 확신하지 못한다.

원인은 두 겹이다:

1. Piper 한국어 음성(`ko_KR-kss-medium`)은 라틴문자를 읽지 못한다. `ko-tts.mjs` 에
   라틴문자 처리 로직이 아예 없다 — 그래서 대본에 `re0` 라고 쓰면 소리가 안 나거나
   깨진다. 대본 작성자가 살아남으려고 "리제로"라고 음차한 것이다.
2. 화면은 그 제약을 안 받으니 원본 식별자를 그대로 썼다. 두 매체가 각자 최적화한 결과가
   서로 어긋났다.

## 그래서 어떻게 쓰나

**한국어 이름을 먼저 정하고, 화면과 나레이션에 둘 다 그것을 쓴다.**

프로젝트를 시작할 때 용어 사전을 만들어 `BRIEF.md` 에 적어둔다:

| 원본 식별자 | 화면에 쓸 말 | 나레이션이 읽을 말 |
|---|---|---|
| `re0` | 다시쓰기 | 다시쓰기 |
| `readchk` | 지시 확인 | 지시 확인 |
| `debloat` | 군더더기 덜기 | 군더더기 덜기 |
| `depth` / `breadth` | 깊게 / 넓게 | 깊게 / 넓게 |

한국어 이름은 **기능을 설명하는 말**로 짓는다. 음차(`리제로`)는 원본을 모르는 사람에게
아무 정보도 주지 않으므로 최후의 선택지다.

## 원본 식별자를 꼭 보여줘야 한다면

저장소 이름·명령어·URL 처럼 **사용자가 그대로 타이핑해야 하는 문자열**은 예외다. 이때는
나레이션에서 읽지 말고 화면에만 띄운다:

- 나레이션: "저장소에서 직접 확인해보세요." ← 주소를 읽지 않는다
- 화면: `github.com/LilMGenius/paperthin` ← 눈으로 읽을 것만

읽지 않는 문자열은 화면에 오래 머물게 하고(최소 2.5초), 나레이션은 "여기", "저장소에서"
같은 지시어로 화면을 가리키기만 한다.

## 검사

`check-script.mjs` **규칙 7**이 `SCRIPT.md` 발화 블록 안의 라틴문자 연속열을 잡아 경고한다.

```
⚠ 규칙 7  line-04: 나레이션에 라틴문자 "re0" — 화면 표기와 일치하는지 확인하라
```

에러가 아니라 경고인 이유: 위의 예외(읽지 않는 URL 등)가 정당하게 존재하기 때문이다.
경고가 뜨면 **화면 텍스트를 열어서 실제로 일치하는지 눈으로 확인하라.** 자동으로는
판정할 수 없다.
